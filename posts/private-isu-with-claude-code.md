# Claude Code に private-isu を3時間回させたら 873,466点だった

ISUCON の練習に [private-isu](https://github.com/catatsuy/private-isu) を使って、**計測から改善・デプロイ・記録まで全部 Claude Code に回させたらどこまで行くのか**を試しました。

**事前準備はしていません。** private-isu のアプリコードもレギュレーションも当日その場で読ませています（レギュレーションはAMIに同梱されていないので、上流から取ってこさせるところから）。事前に用意してあったのは、環境構築用の自作CLI だけです。

**プロンプトもほとんど打っていません。** 最初に方針だけ書いたものを1つ投げて、あとは短い質問と方向修正が20回ほど。「isuenvのCLIを使って」「言語はGoで」「ベンチマーカーは編集も読解もしない」くらいで、改善そのものの指示は出していません。**コードは1行も書いていません。**

- リポジトリ: [kyosu-1/private-isu-2026](https://github.com/kyosu-1/private-isu-2026)
- 環境構築に使った自作CLI: [kyosu-1/isuenv](https://github.com/kyosu-1/isuenv)

## 環境

環境構築には自作の [isuenv](https://github.com/kyosu-1/isuenv) を使いました。ISUCON の過去問と private-isu の練習環境を、公開AMIから EC2 にコマンド一発で作って壊せる CLI です。

```sh
isuenv up private-isu --nodes 1 --bench --ttl 6h
```

private-isu のレギュレーションは **EC2 1台構成が前提**で、「起動したインスタンス以外の外部リソースを利用する行為（他のインスタンスに処理を委譲するなど）は禁止する」と明記されています。なので競技サーバーは `c7a.large`（2 vCPU / 3.7GB）1台のまま最後まで通しました。ベンチマーカーは競技対象外なので別インスタンスです。

## 進め方

最初にルールとして固定したのはこれだけです。

- **計測なき改善は禁止。** 変更前に必ず実測の根拠を示す
- **1改善 = 1コミット = 1ベンチ。** 混ぜない
- **スコアが下がったら即revert。** 粘らない
- **サーバー上で直接編集しない。** ローカルの git が正で、反映は `make deploy` だけ

そのうえで `make bench` を叩くと、ログ初期化 → ウォームアップ → ベンチ → alp / pt-query-digest / vmstat / pidstat の収集 → スコアログへの追記まで自動で走るようにしてもらいました。あとは延々これを回してもらうだけです。

最終的に計測64回・コミット50件。全部の改善にコミットメッセージと `measurements/` の実測根拠が残っています。

## おわりに

**定石を知らなくても、計測さえ回っていれば勝手に定石にたどり着く**、というのが一番の感想でした。インデックスも N+1 も静的ファイル配信も、こちらから一切示唆していません。alp とスロークエリを読ませたら順に潰していきました。

ただしここは割り引いて読む必要があります。private-isu は有名な練習問題で、解法の記事も大量に公開されています。**学習済みの知識をなぞっただけ**という可能性は十分あります。本当に計測から辿り着いたのかは、初見の問題で試すまで分かりません。

このくらいのことが3時間で終わるなら、当日の比重は「速く書くこと」から「何を測るか決めること」と「エージェントを走らせる土台を先に作っておくこと」に移ります。今回いちばん効いたのも、`make bench` を最初に整えたことでした。

そのうえで、今回は1人でやったから成立していた、という点が残ります。本番は3人チームで、エージェントを3人分走らせれば改善案は3倍出てきますが、**ベンチマーカーは1台しかありません。** 同時には回せないし、同じサーバーに2人が反映したらどちらが効いたのか分からなくなります。

環境を人数分立てる案も成立しません。今回ベンチ機のインスタンスタイプを変えただけで、**同一コードのスコアが67,416点動きました**。別環境で出した数字同士は比較できないので、各自が自分の環境で測っても優劣を決められません。

実際に小さく踏んでもいます。別作業用に出したサブエージェントがベンチの最中にサーバーを触り、計測を汚染しました。3人がエージェント経由で同じサーバーを触れば、これが常時起きます。

コードのコンフリクトはエージェントが解消してくれます。**チームで詰まるのは計測の順番のほう**で、ここをどう捌くかが本番までの課題です。
